# ADR-0003 — Ratification of the Engineering Prompt Class

**Status:** Accepted
**Date:** 2026-08-02
**Decision maker:** Maintainer (Constitution Article 6)
**Related:** Blueprint §14 unknown U-4 (decision D-14); Baseline §6; ADR-0002

## Context

Blueprint §14 records U-4: the `playbooks`/`prompts` artifact classes exist
in the repository scaffold without ratified standing ("ratify or retire").
On 2026-08-02 the Maintainer directed that the Engineering Prompt Library
is an approved repository artifact and personally committed its first
document (`docs/prompts/WP15_Architecture_Completion_Prompt.md`). This ADR
records the decision and bounds the new artifact class.

## Decision

"Engineering Prompt" is a ratified artifact class with the following
properties:

- **Home:** `docs/prompts/`.
- **Purpose (single):** reusable, self-contained instructions for
  executing a defined engineering work package.
- **Authority: none.** Prompts are derived, informative artifacts. They
  direct work; they never define architecture, meaning, or decisions
  (L-5, L-8, INV-5, INV-6).
- **Derivation rule:** every statement in a prompt must be derived from
  ratified artifacts (Constitution, Baseline, Blueprint, Doctrine,
  Accepted ADRs). Gaps are marked as explicit TODOs naming the blocking
  decision; they are never filled by invention (CN-14, CN-30).
- **Output rule:** artifacts produced by executing a prompt acquire
  authority only through the normal forward pass (Issue → RFC → ADR →
  Specification → implementation → review). A prompt is never citable as
  authority in any dispute.
- **Conflict rule:** a prompt that contradicts a ratified document is
  defective and must be revised toward the ratified document (Baseline
  precedence), never the reverse.

This resolves U-4 for **prompts**. The status of **playbooks** remains
UNKNOWN and open under D-14.

## Consequences

- `docs/prompts/README.md` defines the library's conventions and index.
- Prompt library maintenance is routine engineering work (Article 7: no
  per-prompt ADRs required).
- The Blueprint's artifact universe gains one derived artifact type; this
  is a MINOR descriptive update to be reflected at the next Blueprint
  revision.
