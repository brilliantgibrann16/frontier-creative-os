## Context

Every mechanical prerequisite of P03.1 was satisfied before this
decision: the RFC-0002 (N-B + N-C) identifier-scheme text is merged
into the S04 container (PR #37, Maintainer-authored); the source RFCs
are Accepted (RFC-0001 — ADR-0006; RFC-0002 — ADR-0004 and ADR-0008;
RFC-0008 — ADR-0004); the program register is current (PR #38). What
remained was the ratification decision itself: Article 6 assigns final
approval of specifications to the Maintainer, Article 7 requires the
decision to be recorded as an ADR, and the S04 security requirements
demand that no AI-authored content enter Ratified status without the
human decision path (INV-5).

On 2026-08-12 the Maintainer decided the surface explicitly and in
writing, covering all six points of the documented decision surface.
This ADR is the authoritative record of that decision. It introduces
no option beyond the written directive (CN-14), assigns no clause ID,
enumerates no clause inventory, ratifies no namespace token, and
defines no index schema.

## Decision

1. **Ratification act.** The S04 Language Definition container
   specification is **Ratified** exactly as it exists on authoritative
   `main` at the moment of decision — commit
   `b879605535305a98ea3b945db10dadb55c8153e2` (merge of PR #38), file
   `specs/S04-language-definition.md`, blob
   `8db4d5f214cc52f888a20a1c6151693dabc3e0bd` (5932 bytes). The
   ratified text is not modified by the ratification decision itself.

2. **Scope — container-only.** Ratification covers the container
   structure and its currently defined container-level requirements
   and checks. It does **not** ratify any Stage 0 language syntax,
   grammar, or semantics, any clause inventory, any concrete namespace
   token, or any content marked BLOCKED or awaiting its own decision
   path. Content criteria remain unratified until their own decision
   path completes (per-clause ratification, P03.3).

3. **Freeze point (RFC-0002 OQ3 — discharged).** The Maintainer
   explicitly accepts ADR-0008 decision 5: this container ratification
   is the binding freeze point for the identifier / clause-numbering
   scheme. From this ratification forward the freeze is authoritative;
   any later change that would move frozen structure travels the
   applicable RFC → ADR governance path (INV-18; S04 State machines).
   RFC-0002 OQ2 (mirror ID display) remains open.

4. **RFC-0008 M-B trigger — interpreted.** For the recorded sequence,
   "first specification ratification" (RFC-0008 §Consequences;
   ADR-0004) means this S04 container ratification. The M-B
   clause-index schema work (P03.4) is therefore the next authorized
   P03 decision/work item. The concrete schema is **not** invented or
   finalized by this ADR and must be established through its own
   recorded decision path.

5. **Article 7 quality gate — judged sufficient.** The Maintainer
   explicitly judges the S04 container-level validation rules
   sufficient for container ratification; currently blocked
   content-level validation does not prevent ratifying the container
   structure. This judgment does not ratify the blocked content
   criteria.

6. **Status update.** As the mechanical consequence recorded by S04's
   own sequence flow (Draft → In Review (PR) → ratification ADR → …),
   S04's status changes from In Review to **Ratified (container-only)**
   in the same change as this ADR. The update covers exactly the two
   status statements in the document — the header status field and the
   Data-model lifecycle sentence whose "until then … In Review" clause
   this ratification discharges — and nothing else.

## Consequences

- **G-SPEC(S04) is MET, container-only.** The PROGRAM.md gate table
  records it in this same change. Programs gated on ratified S04
  *clauses* (e.g. P04) remain gated: this ratification produces no
  clauses.
- **The identifier/clause-numbering freeze is binding.** Renumbering
  after ratification is prohibited (S04 Error model); movement of
  frozen structure requires the RFC → ADR path.
- **P03.3 remains blocked** — no recorded decision enumerates the
  Stage 0 clause inventory; nothing in this ADR derives one.
- **P03.4 becomes the next decision surface** — the M-B concrete
  schema comes due per decision 4 and has no recorded definition yet.
- **P03.5 remains blocked** behind the P03.4 index.
- **Amendment path.** The ratified container is corrected by
  supersession through RFC → ADR, never edited in place (INV-18; S04
  State machines: "post-ratification change is amendment via RFC +
  ADR, never silent edit").
- **No implementation is authorized by this ADR.** CN-14 stands.
- The S04 charter §7 register and the PROGRAM.md records update in
  this same change (program-record convention, PRs #35/#36/#38).
