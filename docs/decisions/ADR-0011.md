## Context

After ADR-0010, three recorded surfaces blocked the remainder of P03:
the Stage 0 clause inventory (P03.3 — no recorded decision enumerated
it), the `spec.version` value the S04 sidecar needs before
instantiation (ADR-0010 follow-up 2), and the drift-checker
implementation authorization (ADR-0010 follow-up 1 — "not begun
without its own authorization"). On 2026-08-12 the Maintainer decided
all three explicitly and in writing, each with deliberately narrow
scope. This ADR is the authoritative record (Article 7; L-8 / INV-8)
and records the directive without addition (CN-14).

## Decision

1. **Stage 0 clause inventory (P03.3) — minimal contract inventory,
   ratified.** The Stage 0 clause set of S04 is a minimal contract
   inventory: it enumerates only obligations already authoritative on
   `main` and introduces no new syntax, grammar, language or runtime
   semantics, compiler or execution behavior, namespace token,
   implementation, performance, or product requirement, architecture,
   or design policy. The inventory is exactly twelve clauses —
   S04#1.1, S04#1.2, S04#1.3, S04#2.1, S04#2.2, S04#2.3, S04#3.1,
   S04#3.2, S04#3.3, S04#3.4, S04#4.1, S04#4.2 — entering the
   ratified S04 text through the amendment path (proposal RFC-0018 →
   this recording ADR, in the same decision cycle — S04 §Sequence
   flows, step 2; INV-18). Each clause carries a stable N-C identifier
   on the grandfathered document ID `S04` (ADR-0008), a category from
   the ratified four-value vocabulary, and explicit source citations
   to its governing decision. Anything not derivable from an
   authoritative source stays out: language content is future content
   outside Stage 0's contract inventory and enters only through the
   amendment path.

2. **S04 `spec.version` = `1.0.0` — narrow.** This is the current
   version value of the ratified S04 container, used only where
   required to instantiate the M-B sidecar. It establishes no
   specification-versioning policy, does not resolve RFC-0009
   language versioning, and defines no global versioning system;
   future versioning policy travels its own recorded decision path.

3. **Sidecar instantiated (ADR-0010 follow-up 2 discharged).**
   `specs/S04-language-definition.index.yaml` exists with exactly the
   ADR-0010 decision 5 schema: `spec:` (`id: S04`,
   `version: 1.0.0`) plus the twelve clause entries (`id`, `category`,
   `title`, `status`, `source`), in clause-ID order, every entry
   `status: ratified`, every `source` pointing at the authoritative
   prose file. No extra fields.

4. **Drift checker authorized and implemented (ADR-0010 follow-up 1
   discharged).** `tools/checks/check_clause_index.py` implements
   exactly the ADR-0010 decision 11 checks — missing index entries,
   index entries with no corresponding clause, duplicate clause IDs,
   invalid category values, invalid status values, invalid identifier
   syntax, and broken source references — for every
   `specs/<spec>.index.yaml` sidecar. Standard library only (CN-26),
   mechanical only (L-10), offline, deterministic; it never modifies
   any file, never creates clauses or identifiers, never auto-fixes
   drift, and fails non-zero with one actionable diagnostic per
   finding. Regression tests live in
   `tests/test_check_clause_index.py` (pytest, `tmp_path`, per
   TESTING_CONVENTIONS). The checker does **not** join the CI gate
   set: the RFC-0011 E-A set (tests + link checks + ID checks) is
   unchanged, and gate-set expansion is decision-level (PROGRAM.md
   P01). Its regression tests run under the existing CI test job like
   every other test.

5. **Clause declaration convention (mechanical).** In specification
   prose a clause is declared by exactly one Markdown list line
   beginning `- **<clause ID> — <title>.**`. This is the convention
   the checker parses; it encodes no semantics and ranks below the
   prose it marks (L-10).

6. **Ratified-text amendment — exact scope.** The S04 amendment
   consists of: the new §Stage 0 clause set; the status-header update
   ("Ratified (container: ADR-0009; Stage 0 contract clause set:
   ADR-0011)"); the discharge or requalification of exactly the
   markers this decision cycle resolves (Scope clause-content marker,
   Interfaces schema marker, Data-model language-content marker, API
   contracts index reference, Testing-requirements marker, Acceptance
   content criteria); and one Traceability row. No other ratified
   sentence changes. ADR-0009 and ADR-0010 are not modified.

7. **CN-9 recorded exception.** Every ratified clause requires ≥1
   conformance test (CN-9); the ratified Testing-requirements text
   permits recorded exceptions. No conformance suite exists (G-CONF
   open; P12 gated), so CN-9 closure for the twelve Stage 0 contract
   clauses is recorded here as an explicit exception that discharges
   when P12 produces clause-traced tests. Until then no test claims to
   verify a clause (TESTING_CONVENTIONS §4 stands).

8. **P03.5 — not decided here.** Wiring the clause-index check into
   the CI gate set remains an open Maintainer decision: gate-set
   expansion is decision-level (PROGRAM.md P01, "Gate-set expansion is
   decision-level and out of scope"), and the 2026-08-12 directive
   explicitly forbids changing CI required-gate semantics.

## Consequences

- P03.3 is executed; ADR-0010 follow-ups 1 and 2 are discharged.
- The ADR-0009 freeze now covers the twelve clause IDs: assigned
  exactly once, never renumbered, deterministic ordering preserved.
- G-SPEC(S04) covers the container plus the Stage 0 contract clause
  set. The contract inventory defines no language content, so
  content-dependent programs (e.g. P04, the compiler) still have no
  implementable clauses; nothing in this ADR unblocks them.
- Program registers (S04 charter §7, PROGRAM.md gate ledger and P03
  entry, `tools/checks/README.md`, RFC index) are updated in the same
  change; `docs/derived/` is regenerated by the official generator.
- Per Article 6, the Maintainer's merge of this decision cycle's PR is
  the approving act for the recorded amendment text.
- The knowledge-mirror sync for this ADR follows the merged state
  (P02.3; mirror-follows-repository).

### Judgment calls disclosed (Baseline §12)

- **Category assignment:** every Stage 0 contract obligation is
  categorized `defined` because each is fully determined by its
  recorded source decision, leaving no implementation-defined,
  unspecified, or undefined latitude. No other category assignment was
  derivable.
- **Declaration convention:** the `- **<ID> — <title>.**` line format
  (decision 5) is the minimum mechanical convention the checker needs
  to locate clauses in prose; it was chosen, not derived, and is
  recorded here so it is decision-backed.
- **N-C fragment form:** `S04#<major>.<minor>` instantiates RFC-0002's
  recorded hierarchical dotted form (`SPEC-LANG-0007#3.2.1`) on the
  grandfathered `S04` token; two levels suffice for twelve clauses.
- **Checker strictness:** every clause declared in prose must be
  indexed regardless of status (lifecycle visibility, ADR-0010
  decision 8), and schema deviations (extra fields, malformed YAML)
  are reported as findings rather than silently tolerated.
- **CN-9 exception:** recorded through the exception mechanism the
  ratified Testing-requirements text itself provides.
