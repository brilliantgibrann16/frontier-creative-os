## Context

Following the full implementation, spec-derived testing, and official S13 conformance self-certification of the **Stage 1 W-B Interchange Kernel** (**P04.0–P04.5**, **P12.1–P12.4**, PR #51–PR #60, claim `CLAIM-FSL-1.0-TOOLS.COMPILER.FSL-0.1.0-STAGE1.WB`, gate **`G-CONF` MET**), RFC-0023 was submitted and merged to frame the capability-stage transition from Stage 1 to Stage 2 (`S04#1.2`) and open four discrete Maintainer decision questions (**D1–D4**).

On 2026-08-21, the Maintainer issued explicit, binding written decisions resolving the entire RFC-0023 decision surface:

> **D1: D1-A** (Enter Stage 2 now)
> **D2: S2-B** (Typed Data Model + Pure Deterministic Expressions)
> **D3: D3-A** (Static Evaluation Only; no S06 runtime behavior)
> **D4: D4-A** (Additive extension within `schema_version: "fsl/1.0"`, preserving Stage-1 compatibility)

This ADR is the authoritative, binding record of those decisions and of the acceptance of RFC-0023 (Constitution Article 6, Article 7; L-8 / INV-8), recorded without addition or invention (CN-14). It constitutes the recording ADR of the Stage 2 capability transition and S04 amendment cycle (S04 §Sequence flows, step 2; INV-18).

## Decision

1. **D1 — Stage Transition Timing: Enter Stage 2 Now (Option D1-A).**
   Progression from Stage 1 (interchange kernel) to Stage 2 (data model & expressions) is formally authorized pursuant to `S04#1.2`. Wave 3 language specification and compiler capability development are unblocked.

2. **D2 — Stage 2 Scope Package: Package S2-B (Typed Data Model + Pure Deterministic Expressions).**
   The normative boundary of Stage 2 comprises:
   - **Typed Data Model Core (§9):** Scalar types (`string`, `integer`, `float`, `boolean`), compound structures (`record`, `list`, `map`), explicit type annotations, and schema validation rules (`S04#9.1`–`S04#9.4`).
   - **Pure Deterministic Expressions (§10):** Side-effect-free, total, and deterministic pure expressions (arithmetic, boolean logic, string operations, collection indexing, conditional branching `if/then/else`, and declarative invariant assertions) (`S04#10.1`–`S04#10.7`).
   - **Explicit Non-Scope:** Dedicated surface syntax (Package S2-C) is rejected/deferred for Stage 2. Expressions are expressed as structured JSON AST nodes within the concrete interchange syntax.

3. **D3 — Runtime Relationship: Static Evaluation Only (Option D3-A).**
   Stage 2 expression evaluation is performed strictly at compile and validation time (static constraint checking, constant folding, and declarative invariant verification). No runtime execution semantics are ratified; S06 runtime behavior remains gated and is not unblocked or implemented by this decision.

4. **D4 — Compatibility & Versioning Strategy: Additive Extension to `fsl/1.0` (Option D4-A).**
   Stage 2 constructs are additive extensions within `schema_version: "fsl/1.0"`. All ratified Stage 1 W-B artifacts remain 100% valid Stage 2 artifacts without schema increment. Existing Stage 1 conformance claim `CLAIM-FSL-1.0-TOOLS.COMPILER.FSL-0.1.0-STAGE1.WB` remains fully intact and valid.

5. **RFC-0023 is Accepted; S04 Stage 2 Clauses Ratified.**
   RFC-0023 is accepted in full. Eleven new normative clauses (`S04#9.1`–`S04#9.4` and `S04#10.1`–`S04#10.7`) enter `specs/S04-language-definition.md` through the amendment path, and are indexed in `specs/S04-language-definition.index.yaml` under `category: defined` and `status: ratified`. All clause identifiers are frozen per `S04#3.2`.

---

## Consequences

- **S04 Language Definition:** S04 is amended to include the §Stage 2 clause set (§9 Typed Data Model Core and §10 Pure Deterministic Expressions). Total ratified S04 clauses expand from 25 to 36.
- **S05 Compiler Boundary:** Unblocks subsequent P04 Stage 2 compiler realization work packages to parse and validate type annotations and evaluate pure static expressions.
- **S06 Runtime:** Remains independently gated. Zero runtime execution authority or runtime behavior is introduced.
- **S13 Conformance & Verification:** Existing Stage 1 W-B conformance suite and standing claims remain 100% valid; Stage 2 conformance fixtures will be added as P04/P12 Stage 2 work packages execute.
- **Backward Compatibility:** 100% preserved. All Stage 1 artifacts continue to parse and validate cleanly under `schema_version: "fsl/1.0"`.
