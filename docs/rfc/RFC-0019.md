# RFC-0019 — S04 Stage 1 Language-Content Scope (Minimum P04 Unlock)

**Status:** In Review · **Date:** 2026-08-14 · **Frames:** the Stage 0 →
Stage 1 capability-stage transition (S04#1.2) and the P04
language-content prerequisite
**Subsystem:** S4 · **Decision-framing: no option is selected; the
transition and its scope are Maintainer decisions (Article 6, Article 7)**

## Summary

Define the exact language-content decision surface that stands between
the ratified S04 Stage 0 contract (ADR-0011) and the start of P04, and
present the admissible Stage 1 scope packages neutrally. Per S04#1.2,
entering any stage is a Maintainer decision travelling the RFC → ADR
path and is never entered implicitly; this RFC is the proposal frame
for that decision. It proposes **no syntax, no grammar, no semantics,
and no clause text**: if a Stage 1 scope is decided, the clause content
itself travels one or more subsequent S04 amendment cycles (proposal
RFC → recording ADR — S04 §Sequence flows, step 2; INV-18).

## Motivation

P04 (Compiler) is gated on ratified S04 clauses with implementable
language content plus the ratified S05 compiler-boundary contract
(PROGRAM.md §5 P04; WBS P04.0; DEPENDENCY_GRAPH edge "P04 | P03
(ratified clauses), P11, P12, G-CI"). The Stage 0 contract inventory
deliberately defines no language content (ADR-0011, Decision 1), so
G-SPEC(S04) is met while P04 still lacks implementable clauses
(PROGRAM.md §4). The S04 charter §7 records "language content beyond
the Stage 0 contract inventory (amendment path)" as a remaining
Maintainer decision. Absent a recorded scope decision, any
language-content drafting would resolve the surface by invention
(CN-14; Doctrine §14). This RFC converts that hazard into a recorded
decision frame.

## Assumptions (all already recorded; reopened by nothing here)

- A-1: Identity is I-D — an interchange/definition core (I-A scope)
  with a staged evolution path toward executable semantics (ADR-0006,
  Decision 1; S04#1.1).
- A-2: The staging discipline is ratified: stages are explicit and
  ordered; execution-facing semantics beyond Stage 0 are deferred
  without being foreclosed (ADR-0006, Decision 3; S04#1.2).
- A-3: The only runtime in scope is the S-B validation-evaluation
  runtime, holding zero defining authority (ADR-0006, Decision 2;
  S04#1.3; Baseline L-3).
- A-4: Consumers are humans authoring, tools consuming, and AI systems
  doing both, symmetrically and stage-invariantly (ADR-0007, Q1;
  S04#2.2); success criteria are the Article 1 metric per ADR-0007, Q2
  (S04#2.3).
- A-5: The name Frontier Specification Language is retained (ADR-0006,
  Decision 5, Q4).
- A-6: Post-ratification change to S04 is amendment via RFC + ADR,
  never silent edit (S04#3.4; INV-18).
- A-7: Prose stays authoritative; the sidecar index is derived hygiene
  (S04#4.1, S04#4.2; ADR-0010).
- A-8: The Phase 0 prototype constrains nothing (L-7, INV-7); no
  namespace token is used or created (ADR-0008).

## Decision classes (no hidden decisions)

### A. Already decided — inputs, not open questions

Identity (ADR-0006 D1); staging discipline (D3); runtime scope S-B
(D2); packaging N-no (D4); consumers and success criteria (ADR-0007);
identifier scheme, grandfathering, token discipline (ADR-0004,
ADR-0008); container ratification and freeze point (ADR-0009); M-B
posture and concrete sidecar schema (ADR-0004, ADR-0010); the twelve
Stage 0 contract clauses (ADR-0011); behavior categorization obligation
(S04#3.3; Baseline §10); specification completeness obligations —
every construct in scope has validity conditions and defined meaning,
or is explicitly labeled (Baseline §10; CN-6).

### B. Proposed for decision by this RFC (the Maintainer decisions)

- **D1 — Stage transition.** Enter Stage 1 now, or defer with a
  recorded review point (DP-15). Entering is what opens Wave 2.
- **D2 — Stage 1 content-scope package.** One of W-A / W-B / W-C
  below (only meaningful if D1 = enter).
- **D3 — Type/data model disposition.** Whether a type/data model is
  inside the Stage 1 scope or is explicitly deferred as labeled
  territory (Baseline §10 labels; GL-2 favors narrow-complete scopes —
  cited as recorded guidance, not as a choice).
- **D4 — Determinism requirement.** Whether Stage 1 validation
  outcomes must be deterministic for identical input artifacts, or
  that territory is explicitly labeled instead. (Conformance is set
  containment of observable behavior — Blueprint §13, property 4;
  nothing ratified today decides determinism either way.)

### C. Deferred to later staged evolution (not proposed, not decided)

Execution-facing semantics beyond validation-evaluation (Stage ≥ 2 —
ADR-0006 D3); the full language versioning scheme (RFC-0009 window;
must encode capability stages); the full compatibility policy
(RFC-0005 window); conformance levels (ADR-0004, future work);
namespace tokens (ADR-0008 — none required by any decided dependency);
standard library scope (P06); optimization; product/tooling surfaces.

### D. Blocked by other existing decisions (cannot be decided here)

The S05 compiler-boundary contract (its own specification ratification;
B-06, B-08); S13 ratification and the conformance harness (G-SPEC(S13),
G-CONF; CONFORMANCE_FRAME §2–§3); G-CI closure (P01.5 Maintainer
console action); RFC-0002 OQ2 (mirror ID display); RFC-0014/RFC-0015
routing and definition (P15.3).

## Design space — Stage 1 scope packages (without choice)

| # | Package | Contents | P04 effect if ratified | Trade-offs |
| --- | --- | --- | --- | --- |
| W-A | Validity kernel | Artifact model + validity conditions + validation-outcome contract (accept/reject; rejections cite violated clauses), every behavior categorized (S04#3.3) | Gives P04 judgeable clauses, but no concrete input form: the S05 input-acceptance contract cannot bind to a serialization that does not exist | Smallest ratifiable content; near-certain second cycle before S05 can ratify |
| W-B | Interchange kernel | W-A + one concrete serialized interchange form for FSL artifacts | The smallest package under which the S05 input-acceptance contract becomes specifiable; matches the I-D "interchange" scope | Adds a format decision; the format's own design space (existing boring format per GL-15/DP-28 vs bespoke form) is a recorded sub-decision for the amendment cycle, not chosen here |
| W-C | Authoring kernel | W-B + human-authorable surface syntax + grammar | Serves the "humans authoring" consumer class (S04#2.2) directly at Stage 1 | Largest first-cycle surface; grammar work immediately pressures the unratified tooling contract (B-06) |
| W-D | Defer | No Stage 1 entry; record a review point (DP-15) | P04 remains gated; Wave 2 does not open | Preserves option value; leaves the critical path parked at a recorded decision |

Coherence note (analysis, not choice): every package preserves A-1…A-8;
none forecloses later stages; W-A ⊂ W-B ⊂ W-C, so a smaller package
never blocks a later amendment cycle adding the rest.

## Minimum unlock analysis

The smallest ratifiable language-content contract that would allow P04
to begin is the set of ratified S04 clauses that define: (1) what a
Stage 1 FSL artifact **is** (artifact model); (2) when it is **valid**
(validity conditions, four-category complete per S04#3.3 and Baseline
§10); (3) what a conforming processor observably does with valid and
invalid artifacts (validation-outcome contract); and (4) a concrete
input form, without which the S05 input-acceptance boundary cannot be
written. Nothing else — no execution semantics, no type-system
ambition, no library, no optimization, no product surface — is needed
for P04 entry. Even then, **acceptance of this RFC does not make P04
executable**: the full unlock chain is ratified Stage 1 clauses (via
amendment cycles) + ratified S05 contract (B-06/B-08) + G-CI (P01.5
console) + P11 spec-derived evidence conventions + the P12 judge
(G-SPEC(S13), G-CONF).

## Open Questions

Exactly the four Maintainer decisions of class B: D1 (enter Stage 1 or
defer), D2 (W-A / W-B / W-C), D3 (type/data model in or labeled out),
D4 (determinism required or labeled). No other question is opened.

## Consequences

- **If D1 = enter and a package is chosen:** the acceptance ADR records
  the stage transition and scope (S04#1.2 satisfied by the recorded
  path); clause drafting then travels one or more S04 amendment cycles
  with per-clause ratification, sidecar updates (ADR-0010 schema), and
  drift-checker coverage; the ratified S04 prose is not modified before
  those cycles (INV-18).
- **P04 effect:** after Stage 1 clauses ratify, P04's "ratified
  clauses" prerequisite is met for that scope; P04 entry additionally
  requires the ratified S05 contract, G-CI, P11 evidence conventions,
  and the P12 judge, exactly as registered. Nothing here marks P04
  executable.
- **If D1 = defer (W-D):** Wave 2 stays closed at a recorded review
  point; no blocker state changes.
- This RFC decides nothing by existing (L-8/INV-8); RFC-0002 OQ2,
  RFC-0005, RFC-0009, and P15.3 questions are untouched.

## Recommendation (non-binding)

None. Per the Maintainer's standing ruling the language is designed
collaboratively (RFC-0001 §Recommendation); the stage transition and
its scope are identity-adjacent decisions, so this RFC supplies the
decision frame only.
