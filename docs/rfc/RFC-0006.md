# RFC-0006 — Reference Implementation Policy

**Status:** In Review · **Date:** 2026-08-02 · **Resolves:** U-7
**Subsystem:** S5 Compiler (policy applies to all official implementations)

## Summary

Decide whether FCOS designates a "reference implementation" and, if so,
what that status means — given the hard bound that no implementation may
acquire defining authority (CN-8, L-3, P-1).

## Motivation

U-7. The historical failure mode is well documented across language
ecosystems: the first implementation becomes the de facto specification
(risk R-4, "compiler-is-the-spec", rated Critical). The policy must exist
before the first line of the first official implementation.

## Assumptions

- A-1: Under every option, divergence between any implementation and the
  specification is a defect in the implementation (L-2).
- A-2: The conformance suite, not any implementation, is the judge
  (INV-16).

## Design Space

| # | Option | Trade-offs |
| --- | --- | --- |
| R-A | No reference implementation ever; all official implementations are peers under the suite | Cleanest authority story; loses a convenient "executable illustration" of the spec |
| R-B | Designated reference implementation with explicitly *zero* defining authority, used as illustration only | Practical aid for spec authors and implementers; constant vigilance cost — the label invites authority creep (R-4) |
| R-C | Reference implementation as executable specification (authoritative) | Explicitly forbidden territory: violates P-1/L-3/CN-8; listed for completeness and rejected structurally |

## Open Questions

1. If R-B: what marks distinguish "illustration" from "authority" in
   practice (naming, disclaimers, CI treatment)?
2. Who maintains the first implementation — and does its team overlap
   with spec authorship (separation-of-judge concern, AX-3)?
3. Interaction with U-13: does the reference implementation get
   certified like any other (A-2 suggests yes)?

## Consequences

Decidable in frame now; the concrete implementation plan waits on
RFC-0001 and ratified specifications.

## Recommendation (non-binding)

R-A as default posture; R-B only if spec-authoring experience shows the
illustration value is worth the vigilance cost, adopted by supersession.
