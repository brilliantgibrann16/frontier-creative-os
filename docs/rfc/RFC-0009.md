# RFC-0009 — Language Versioning Scheme

**Status:** In Review · **Date:** 2026-08-02 · **Resolves:** U-10
**Subsystem:** S4 · **Decision blocked by RFC-0001 (D-01); coupled to RFC-0005**

## Summary

Decide how the language itself is versioned — as distinct from document
versioning (already fixed: MAJOR.MINOR per Baseline §12) and from
implementation versioning — and how a program declares which language
version it targets.

## Motivation

U-10. Three version spaces (language, specification documents,
implementations) are easily conflated; conflation is how accidental
promises form (Doctrine §9). The scheme also parameterizes conformance
certification (RFC-0004 L-C) and compatibility policy (RFC-0005 P-B/P-C).

## Assumptions

- A-1: Specification documents already version as MAJOR.MINOR with
  ratified-change discipline (Baseline §12); this RFC does not reopen it.
- A-2: An implementation's version never *is* the language version
  (P-2/L-2 corollary).

## Design Space

| # | Scheme | Trade-offs |
| --- | --- | --- |
| V-A | Single monotonic language version (FSL 1, 2, 3…) | Simple; every release is potentially breaking-scoped; coarse |
| V-B | Semver-like MAJOR.MINOR for the language, decoupled from document versions | Familiar; requires precise definition of "breaking" (depends on RFC-0005's observable-surface answer) |
| V-C | Date-based editions (FSL 2027) + continuous minor evolution | Matches P-B edition mechanism in RFC-0005; meaningless unless that mechanism is adopted |
| V-D | No language version pre-1.0; spec-document version is the only version during design | Honest minimum now; must be explicitly retired at first stable release |

## Open Questions

1. How does a source artifact declare its target version — in-language
   syntax (D-01-dependent) or out-of-band manifest?
2. Do conformance certificates bind to language version, document
   version, or both (RFC-0004 Q2)?
3. Mixed-version interaction: may artifacts of different language
   versions reference each other, and who defines the bridge?

## Consequences

Undecidable before RFC-0001 except V-D's interim rule, which is
decidable now and prevents premature version claims.

## Recommendation (non-binding)

Adopt V-D interim rule by lightweight ADR; decide the stable scheme
together with RFC-0005 after RFC-0001.
