# RFC-0011 — CI Platform and Gate Encoding

**Status:** In Review · **Date:** 2026-08-02 · **Resolves:** U-12
**Subsystem:** S12/S15 · **D-01-independent: decidable now**

## Summary

Decide how Article 9's gate ("CI must pass before any production
release") is mechanically encoded: which classes of checks run, at which
events, and what "passing" attests — without selecting vendors beyond
what the repository host already provides.

## Motivation

U-12; open risk "no-CI" in the Risk Register (rated High since
2026-08-01). Article 9 is currently a promise with no mechanism: the
repository has an empty `.github/workflows/`. Doctrine §13's mechanical
audits (WP30) and CN-9 traceability checks need an execution vehicle.

## Assumptions

- A-1: The repository is hosted on GitHub; GitHub Actions is the
  zero-additional-vendor default. Naming it is a hosting fact, not a
  tooling endorsement (CN-26 satisfied: workflows are portable YAML).
- A-2: CI never defines correctness; it executes judges defined
  elsewhere (suite, audits). CI-as-authority is an illegal reverse flow.

## Design Space

**Check classes (phase-in order candidates):** (1) prototype unit tests
(exist today, 6/6); (2) documentation audits — ID uniqueness, link
integrity, trace closure, ⊑-DAG acyclicity (RFC-0008-dependent for
depth); (3) conformance suite execution (future, post-spec); (4) release
gating per Article 9.

**Encoding postures:** (E-A) minimal now — tests + link/ID checks on every
PR; (E-B) full audit battery pre-designed, phased in as RFC-0008 lands;
(E-C) defer all CI until first release approaches. Trade-offs: E-A pays
down the recorded risk immediately at trivial cost; E-B front-loads
design that RFC-0008's outcome may invalidate; E-C leaves Article 9
unenforceable and the risk open.

## Open Questions

1. Does a failing documentation audit block merge (gate) or only report
   (signal) during the design phase?
2. What attestation does a green run make for release notes (interacts
   with RFC-0005 observable-surface answer)?
3. Are workflow files themselves governed artifacts (review rules)?

## Consequences

Decidable now. E-A closes the Risk Register's oldest open item and makes
Article 9 mechanically meaningful before the first release exists.

## Recommendation (non-binding)

E-A immediately; extend toward E-B as RFC-0008's posture lands.
