# RFC-0008 — Machine-Readable Specification Format

**Status:** In Review · **Date:** 2026-08-02 · **Resolves:** U-9
**Subsystem:** S4/S13 · **Decision blocked by RFC-0001 (D-01)**

## Summary

Decide whether ratified specifications carry a machine-readable
representation alongside prose, and if so, its frame: what is encoded
(clause identity, categories, traceability links, or full semantics),
and which representation is authoritative when prose and encoding
disagree.

## Motivation

U-9. Doctrine §13 mechanical audits (trace closure, ⊑-DAG acyclicity,
CN-27) and CN-9 clause-to-test traceability become dramatically cheaper
with structured clause data. Without a decision, tooling will improvise
formats — a shadow-specification hazard (Baseline §7).

## Assumptions

- A-1: Exactly one representation is authoritative per artifact (AX-1);
  the other is derived and mechanically checked against it.
- A-2: Format choice must not require proprietary tooling (CN-26).

## Design Space

| # | Option | Trade-offs |
| --- | --- | --- |
| M-A | Prose-only; audits parse conventions (headings, ID patterns) | Zero format design cost; audits are fragile regex-craft; traceability best-effort |
| M-B | Prose authoritative + structured clause index (IDs, categories, links) generated or hand-maintained | Cheap mechanical audits; encoding drift must itself be audited; smallest viable step |
| M-C | Structured source (single source) from which prose renders | Strongest consistency; heavy authoring machinery before a single spec exists; premature |
| M-D | Formal/executable semantics encoding | Out of reach before D-01 and mature specs; listed to record it is a future option, not a current one |

## Open Questions

1. Which audits from Doctrine §13 must be mechanical at first spec
   ratification (feeds WP30, U-12)?
2. Where does the clause index live relative to RFC-0003's taxonomy
   outcome?
3. Is the index normative (part of ratification) or derived hygiene?

## Consequences

Frame (M-A vs M-B posture) is decidable now; concrete schema is
D-01-and-first-spec dependent. Deciding M-B's *posture* early lets
RFC-0002's clause-ID rules be designed compatibly.

## Recommendation (non-binding)

Adopt M-B as posture (prose authoritative + minimal clause index), schema
deferred to first specification ratification.
