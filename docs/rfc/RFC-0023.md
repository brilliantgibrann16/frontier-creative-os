# RFC-0023 — S04 Stage 2 Capability-Stage Transition & Scope Framing

**Status:** Accepted (ADR-0016) · **Date:** 2026-08-19 · **Frames:** the Stage 1 → Stage 2 capability-stage transition (S04#1.2) and the Stage 2 language-content scope
**Subsystem:** S4 · **Decision:** Accepted per ADR-0016 (D1: D1-A Enter Stage 2 now; D2: Package S2-B Typed Data Model + Pure Expressions; D3: D3-A Static evaluation only; D4: D4-A Additive extension to `fsl/1.0`)
**Governing Ratifications:** S04 Stage 0 (ADR-0011), S04 Stage 1 W-B (ADR-0013), S05 Compiler Boundary (ADR-0014), S13 Verification & Conformance (ADR-0015), S04 Stage 2 (ADR-0016)
**References:** RFC-0001 (D-01), RFC-0012 (U-14), RFC-0019 (Stage 1 Frame), ADR-0006, ADR-0012, ADR-0016, Baseline §10, Doctrine DP-15, DP-28, GL-2, GL-15, CN-6, CN-9, CN-14

## 1. Summary

Following the full implementation, spec-derived testing, and official S13 conformance self-certification of the **Stage 1 W-B Interchange Kernel** (**P04.0–P04.5**, **P12.1–P12.4**, PR #51–PR #60, gate **`G-CONF` MET**), this RFC defines the exact decision surface standing before **Stage 2** entry.

Per ratified clause **S04#1.2**:
> *"The language capability stages are Stage 0 (minimal contract), Stage 1 (interchange kernel), Stage 2 (data model & expressions), Stage 3 (full language). Progression across stages requires explicit Maintainer authorization via the RFC → ADR decision path."*

This RFC serves as the formal proposal frame for that decision. It presents the admissible Stage 2 scope packages neutrally and opens exactly four Maintainer decision questions (**D1–D4**).

It proposes **no final syntax, no grammar, no semantics, and no binding clause text**: if a Stage 2 scope package is chosen, the clause content itself travels subsequent S04 amendment cycles (proposal RFC → recording ADR per S04 §Sequence flows, step 2; INV-18).

---

## 2. Motivation & Background

1. **Stage 1 W-B Closure:** The Stage 1 W-B kernel (`S04#5.1`–`S04#8.3`) established the single-artifact unit model, self-contained local dependency checking, manifest identity closure, four-category validation outcome model, and concrete JSON interchange syntax.
2. **S05 & S13 Operational Status:** The compiler subsystem (`tools.compiler.fsl`), test harness (`tools.conformance.runner`), canonical fixture corpus (`tests/fixtures/conformance/`), and official judge (`tools.conformance.judge`) have verified Stage 1 compiler conformance with 100% clause totality, publishing standing claim `CLAIM-FSL-1.0-TOOLS.COMPILER.FSL-0.1.0-STAGE1.WB` in `docs/conformance/claims/`.
3. **The Stage 2 Opportunity:** Stage 1 deliberately excluded type systems, expressions, and evaluation semantics (ADR-0012, Decision 3). To advance Frontier Specification Language toward richer specification definitions without accidental invention or ad-hoc creep (CN-14), the Maintainer must determine the Stage 2 entry timing and content boundary.

---

## 3. Assumptions (Already Ratified / Binding)

- **A-1 (Identity):** Language identity is **I-D** — an interchange/definition core with a staged evolution path toward executable semantics (ADR-0006, Decision 1; `S04#1.1`).
- **A-2 (Staging Model):** Capability stages are explicit, ordered, and sequentially gated; execution-facing semantics beyond Stage 1 remain deferred without being foreclosed (`S04#1.2`).
- **A-3 (Runtime Scope):** The only runtime in scope is the **S-B validation-evaluation runtime**, holding zero defining authority (ADR-0006, Decision 2; `S04#1.3`; Baseline L-3).
- **A-4 (Consumers & Metrics):** First-class consumers are humans authoring, tools consuming, and AI systems doing both symmetrically (ADR-0007, Q1; `S04#2.2`); success criteria follow the Article 1 metric (ADR-0007, Q2; `S04#2.3`).
- **A-5 (Interchange Baseline):** The concrete interchange syntax for Stage 1 is UTF-8 RFC 8259 JSON under `schema_version: "fsl/1.0"` (`S04#8.1`–`S04#8.3`, ADR-0013).
- **A-6 (Amendment Path):** Post-ratification modifications follow the proposal RFC → recording ADR sequence, preserving ratified clauses through supersession (`S04#3.4`, INV-18).
- **A-7 (Zero Invention):** No syntax, grammar, or type semantics are binding until ratified by an ADR (Law 3, Law 4).

## 4. Decision Classes

### A. Already Decided (Inputs, Not Open)
- Identity I-D (ADR-0006 D1);
- Runtime scope S-B (ADR-0006 D2);
- Packaging N-no / Program P10 closed (ADR-0006 D4);
- Grandfathered namespace token discipline (ADR-0008);
- Stage 0 minimal contract clauses `S04#1.1`–`S04#4.3` (ADR-0011);
- Stage 1 W-B clauses `S04#5.1`–`S04#8.3` (ADR-0013);
- S05 compiler boundary contract `S05#1.1`–`S05#4.3` (ADR-0014);
- S13 verification & conformance subsystem `S13#1.1`–`S13#4.4` (ADR-0015);
- Gate `G-CONF` satisfied for Stage 1 W-B (P12.4 claim publication).

### B. Proposed for Decision by this RFC (Maintainer Decisions D1–D4)

- **D1 — Stage Transition Timing:**
  - *Option D1-A:* Enter **Stage 2** now. Opens Wave 3 specification and design.
  - *Option D1-B:* Defer Stage 2 entry with a recorded DP-15 review point.
- **D2 — Stage 2 Content-Scope Package:**
  - *Package S2-A (Typed Data Model Core):* Adds scalar types (string, integer, float, boolean), structured types (records, lists, maps), type annotations in declarations, and schema validation rules. No expression language.
  - *Package S2-B (Data Model + Pure Deterministic Expressions):* Adds Package S2-A plus side-effect-free deterministic pure expressions (arithmetic, boolean logic, string operations, collection indexing, conditional expressions `if/then/else`, and declarative invariant assertions).
  - *Package S2-C (Data Model + Expressions + Human Surface Syntax):* Adds Package S2-B plus a dedicated human-authorable surface syntax / grammar that compiles into the concrete JSON AST.
- **D3 — Runtime Relationship (S06 S-B Integration):**
  - *Option D3-A (Static Evaluation Only):* Stage 2 expressions are evaluated strictly at compile/validation time (constant folding, static constraint checking).
  - *Option D3-B (Runtime Evaluation Contract):* Stage 2 defines both static constraints and the formal evaluation contract for the S06 S-B validation-evaluation runtime.
- **D4 — Compatibility & Versioning Strategy:**
  - *Option D4-A (Additive Extension to `fsl/1.0`):* Stage 2 constructs are additive extensions within `schema_version: "fsl/1.0"` (all Stage 1 artifacts remain valid Stage 2 artifacts).
  - *Option D4-B (New Major Schema Version `fsl/2.0`):* Stage 2 increments `schema_version` to `"fsl/2.0"`, with a defined migration/backward-compatibility path.

### C. Deferred to Later Capability Stages (Stage ≥ 3)
- Dynamic mutable state machines;
- Asynchronous concurrency and messaging;
- System I/O, networking, and platform bindings;
- Multi-package dependency resolution (RFC-0007 N-no stands);
- Dynamic code generation / execution.

## 5. Scope Package Comparison

| Dimension | Package S2-A (Data Model) | Package S2-B (Data + Expressions) | Package S2-C (Full Surface) |
|---|---|---|---|
| **Language Expressivity** | Structural declarations with type constraints | Rich declarative constraints, parameterization, and computed values | Human-readable FSL code + JSON interchange AST |
| **Compiler Complexity** | Low (type checker + structural validator) | Medium (AST expression parser, type inference, evaluator) | High (lexer, parser, grammar, AST generator, formatter) |
| **Specification Surface** | ~10–12 new S04 clauses | ~20–25 new S04 clauses | ~35–40 new S04 clauses |
| **S06 Runtime Boundary** | Minimal (schema validation only) | Clear (pure deterministic expression evaluation) | Clear (pure expression evaluation) |
| **Implementation Risk** | Very Low | Low (deterministic stdlib-only evaluation) | Medium (grammar ambiguity, parser maintenance) |
| **Adherence to DP-28 / GL-15** | Highest (boring, simple, predictable) | High (pure, side-effect-free) | Moderate |

---

## 6. Reviewer Recommendation (Non-Binding)

- **D1:** Enter Stage 2 now (**Option D1-A**), building on the stable, conforming Stage 1 foundation.
- **D2:** Select **Package S2-B** (*Data Model + Pure Deterministic Expressions*). This provides the essential semantic power needed for domain specification while keeping AST interchange boring and predictable (JSON-based) without premature grammar bloat.
- **D3:** Select **Option D3-B** (*Runtime Evaluation Contract*), cleanly formalizing the S06 S-B validation-evaluation runtime boundary.
- **D4:** Select **Option D4-A** (*Additive Extension to `fsl/1.0`*), preserving complete backward compatibility with all Stage 1 W-B artifacts.
