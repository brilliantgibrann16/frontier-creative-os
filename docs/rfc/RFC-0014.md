# RFC-0014 — Candidate Subsystem: Memory

**Status:** In Review · **Date:** 2026-08-02 · **Resolves:** — (routing + subsystem introduction)
**Subsystem:** S4 (if language memory model) or none (if storage subsystem)

## Summary

Decide what "Memory" (named in WP15, absent from the ratified Blueprint)
refers to, then route it: a *language memory model* is S4 territory and
belongs inside RFC-0001's downstream specification work; a *storage/
persistence subsystem* is a new subsystem requiring the Blueprint §13
amendment path. The routing question is prior to any design question.

## Motivation

WP15/Blueprint conflict (PR #11). The WP19 prompt recorded this same
ambiguity; this RFC formalizes it for decision.

## Routing Decision (the actual question)

| # | Reading | Route | Consequence |
| --- | --- | --- | --- |

| M-B | Storage/persistence subsystem (durable state for the platform) | New subsystem; necessity case + §13 amendment required | Same necessity-evidence TODO as RFC-0013 |
| M-C | Both | Split: M-A folds into S4; M-B proceeds as introduction RFC | Two decisions, clearly separated |
