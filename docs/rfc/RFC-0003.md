# RFC-0003 — Specification Corpus Location and Repository Taxonomy

**Status:** In Review · **Date:** 2026-08-02 · **Resolves:** U-3 (D-13); D-14 remainder (playbooks)
**Subsystem:** cross-cutting · **D-01-independent: decidable now**

## Summary

Decide the single authoritative home for ratified specifications —
`docs/specifications/` (decided dual-homing path, 2026-08-01) versus the
pre-existing `specs/fcos/` scaffold — and the disposition of the remaining
unratified scaffold classes (`playbooks/`, `prompts/` under `specs/fcos/`
and `build/`).

## Motivation

D-13; Blueprint §14 U-3; Baseline audit finding F-3. Two candidate homes
violate AX-1 by ambiguity even while both are empty. L-6: the scaffold
carries no authority, so its existence is not an argument for keeping it.

## Assumptions

- A-1: The 2026-08-01 Maintainer decision fixed `docs/specifications/`
  as the repository home for dual-homed specifications; it did not
  address `specs/fcos/`.
- A-2: ADR-0003 ratified `docs/prompts/` for prompts; `specs/fcos/prompts/`
  is therefore redundant under any outcome.

## Design Space

| # | Option | Trade-offs |
| --- | --- | --- |
| T-A | Single home `docs/specifications/`; delete `specs/` scaffold | One authoritative location (AX-1); loses the (empty) taxonomy sketch; requires deletion commit |
| T-B | Single home `specs/fcos/`; supersede the 2026-08-01 path decision by ADR | Keeps top-level visibility; contradicts a recorded decision, needs explicit supersession; splits normative docs across two roots (`docs/`, `specs/`) |
| T-C | `docs/specifications/` normative; `specs/` retained as generated/derived output area | Preserves both; requires a ratified generated-content rule; risk of shadow specification (Baseline §7) if discipline slips |

Playbooks disposition (D-14 remainder): ratify as an artifact class by
future ADR when a real need is filed, or retire the empty directories now
(no content exists; retirement is loss-free).

## Open Questions

1. Does any tooling plan (U-9 machine-readable specs) prefer a top-level
   `specs/` root for generated artifacts (interacts with T-C)?
2. Should empty scaffold removal happen in the same change as the
   decision ADR or as separate hygiene?

## Consequences

Any option ends the dual-candidate ambiguity (closes F-3). T-A/T-B are
terminal; T-C requires one additional ratified rule.

## Recommendation (non-binding)

T-A: it honors the recorded 2026-08-01 decision, restores single-home
discipline, and deletes nothing but empty directories. Retire empty
playbook scaffolds; re-ratify later if a need is filed.
