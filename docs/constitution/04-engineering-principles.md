# Article 4 — Engineering Principles

1. Implementation changes are accompanied by tests.
2. Documentation describes only what exists, or is explicitly marked as proposed or pending.
3. All changes flow through feature branches and pull requests. Nothing is committed directly to `main`.
4. Commit messages follow the Conventional Commits specification.
5. Changes are kept small and reviewable; unrelated changes are not mixed in one commit.
6. GitHub is the source of truth for implementation and work tracking. The engineering knowledge base is the source of truth for engineering knowledge. Neither duplicates the other; they reference each other.
7. Verification is automated where practical. A claim that cannot be verified automatically or reproduced manually is treated as unknown.
