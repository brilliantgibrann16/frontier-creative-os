# Article 8 — Compatibility Policy

## Before version 1.0

No stability guarantees are given. Breaking changes are permitted, but each must be recorded in an ADR and noted in release notes.

## From version 1.0

1. Semantic Versioning governs all published artifacts.
2. Breaking changes require a major version increment and a documented migration path.
3. Deprecated interfaces remain functional for at least one minor release before removal.
4. Specifications are versioned. Ratified specifications are amended through the decision lifecycle, never silently edited.
